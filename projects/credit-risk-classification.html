Credit Risk Classification Model

A lender wants to know, before money leaves the building, whether a customer is likely to pay it back. This project builds a model that classifies customers into good, standard, and poor credit risk profiles.

Tools

Python pandas NumPy scikit-learn category_encoders seaborn matplotlib

The problem

A financial company had years of customer credit scores on file but was still assessing applications by hand. Manual assessment is slow, and it suffers from moral hazard and information asymmetry, since the person judging the application never has the full picture. The task was to use that historical data to predict which customers can safely be extended credit.

My approach

I followed the machine learning pipeline end to end rather than jumping straight to a model.

ingestion → wrangling → EDA → feature engineering → training & validation → testing → communication

Most of the real work lived in data preparation. The raw dataset had numeric fields stored as text, with stray characters that had to be stripped with regular expressions before columns like Age, Annual_Income, Num_of_Loan, and Num_of_Delayed_Payment could be converted to their proper types. I profiled distributions with seaborn, checked skew and kurtosis to decide where transformations were needed, and used category encoders to turn categorical features into something a model can learn from.

Cleaning numeric fields stored as text

Encoding categorical features

For the model itself, I tuned a Random Forest and an XGBoost classifier side by side with GridSearchCV using an F1 scorer, and selected the better performer.

The outcome

The finished model sorts customers into good, standard, and poor risk profiles, giving the lender a consistent first pass on every application instead of a judgment call that varies by analyst. The larger lesson for me was that classification accuracy is earned in the cleaning stage. A model trained on columns with the wrong data types is confidently wrong, and no algorithm choice fixes that.
